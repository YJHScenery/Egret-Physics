# 场景参考尺度与动态控制

状态：本文记录整体需求规划。场景控制的模型层抽象接口、谓词枚举后端和世界步边界接入已实现，使用方法与当前限制见 [场景控制接口](scene_control_api.md)。显示尺度、规则编辑界面及用户程序编译仍未实现；下文中超出当前接口文档的功能属于后续规划。

## 显示尺度

物理求解、文件数据与属性输入始终使用 SI 单位。显示参考尺度仅决定物理坐标到渲染坐标的映射，不改变质量、重力、碰撞尺寸、惯性或时间步长。

提供厘米、米、千米、自定义四种预设。用户填写“一格代表多少物理长度”，自定义必须为有限正数；建议将该长度映射为 100 个渲染单位。厘米对应 0.01 m，米对应 1 m，千米对应 1000 m。界面明确显示“一格＝1 cm”等标识，避免与修改物体尺寸混淆。

统一映射为 renderPosition = coordinatePermutation((physicalPosition − renderOrigin) × displayScale)，其中 displayScale = 100 / referenceLengthMeters。形状、约束锚点、曲线、轨迹、力箭头、选中框使用相同映射；拾取、拖拽、测量和 Gizmo 写回必须使用逆映射。相机、近远裁剪面、网格与适应场景按钮按同一规则处理。编辑器、实时仿真器、播放器和视频导出共用该配置。支持以观察中心为渲染原点，以避免千米场景中 float 精度损失。

统一放大不能解决同一场景里“米长木板与纳米厚滑块”的尺寸悬殊。额外提供“显示质点标记”和“最小屏幕标记尺寸”，仅放大标记，不改变碰撞体。实际轮廓与辅助标记应可区分，避免产生错误物理印象。

配置按场景保存；缺失配置的旧场景保留现有显示。新建场景默认米。切换尺度保留物理观察中心，并提供适应所选物体或全部动态物体；巨大地面默认不参与取景边界。

## 用户如何输入条件

默认采用中文规则卡片，不要求脚本。每张卡片由“何时”“如果”“执行”“持续多久”四部分组成。简单操作只显示对象、物理量、比较关系、带单位数值；高级条件通过“同时满足”“满足任意一个”“不满足”组合，初期限制嵌套深度，避免成为程序编辑器。

示例：

- 当仿真时间到 1 秒，对木板施加向右 26 N 的力，持续 2 秒。
- 当滑块离开木板后，立即取消指定拉力。
- 当滑块的 x 坐标超过 10 m，将滑块移出仿真。
- 当两个物体的距离小于 0.2 m 且相对速度小于 0.01 m/s，记录标记。
- 当物体进入休眠，暂停仿真并标记当前时刻。

对象用名称选择，内部保存稳定 ID；重命名不影响规则。物体缺失时显示明确校验信息，不静默指向同名物体。需要区分“两者都休眠”“任意一个休眠”“相对静止”，它们不是同一个条件。

## 条件集合

数值条件支持时间、位置、速度、速率、角速度、角速率、距离、相对位置、相对速度及相对角速度。向量先选择分量或模长，再比较。相对量明确以 A−B 为定义；角速度提供 rad/s 和 °/s 显示单位，运行时统一转换。

比较关系支持大于、小于、近似等于、区间内、区间外。近似等于必须有容差，禁止浮点精确相等。区间统一为左闭右开；上下界、单位和有限性均在开始前验证。

状态条件支持实体是否参与求解、休眠状态、两个实体是否接触。接触依据本步真实接触对，不能以 AABB 相交代替；支持“开始接触”“保持接触”“结束接触”。相对静止依据相对线速度与相对角速度阈值，必要时选择是否要求接触。

每个状态条件提供滞回阈值和可选最短保持时间，减少数值抖动导致的反复触发。以“首次成立”作为默认触发方式；高级模式支持每次由假变真、由真变假、条件成立期间。禁止默认每个求解步重复创建物体。

## 时间与事件语义

支持绝对时间点、绝对时间区间、条件触发事件、相对事件延时以及相对事件持续时间。条件成立时保存实际检测时刻 t_event，后续动作可在 t_event + delay 开始。

规则的时间判断在求解器时间轴上运行，与播放进度和墙钟无关。播放器回放已记录结果，不重新执行规则。重置仿真清除触发计数、事件时间、滞回状态和动作状态。

定时动作可将求解步切分到已知时间边界；状态阈值先提供“下一求解步边界触发”的清晰语义，其检测不确定度不大于当前步长。禁止把每步检测声称为连续时间精确事件。后续可对明确可插值的标量阈值增加事件定位；碰撞事件采用接触流水线的真实事件时间。

## 动作与生命周期

首批动作：启用或停用实体、启用或停用力场或约束、开始或结束指定恒力、设置速度、记录事件、请求暂停。随后支持从模板实例化实体。实体激活用于教学中的“添加”，不是只切换可见性。

“移出仿真”先实现为停用：退出积分、碰撞、施力及约束求解，保留稳定 ID 和历史数据，以支持回放与恢复。永久释放对象另设操作，不能在遍历求解实体时直接 erase。停用实体关联的约束与目标恒力同步停用；恢复时校验端点及配置。位置、速度和可见性分别定义恢复策略。

新实例使用新的 ID；限制最大实例数和每条规则的触发次数。离线文件必须能表达动态实体表或预先登记的模板实例，否则不能只在实时路径支持创建。

## 每步执行效率

文本本身不意味着执行慢：关键是是否每步解析、解释或跨语言调用。默认表单保存为带版本号的结构化 JSON；可选自然语言只用于编辑时生成同一种规则，必须先显示解析结果供用户核对，不进入求解循环。

开始仿真时完成解析、校验、单位换算、对象 ID 绑定和条件树编译。运行时只执行原生 C++ 条件节点或紧凑指令，不做字符串查找、JSON 解析、正则、脚本解释或模型调用。实体句柄带代次校验，不能缓存因场景重建而失效的裸指针。

时间点按最小堆或有序数组调度，避免每步扫描未来时间事件。接触条件共享本步接触对索引；休眠事件共享状态变化；同一对象的常用状态每步采样一次。只有活跃规则参与判断，布尔条件短路求值。持续恒力使用按动作 ID 管理的力源，避免逐步创建场对象。

检测阶段读取同一份已完成求解步的状态快照，产生动作队列；在下一安全步边界统一执行动作，随后刷新场景缓存。不得在条件遍历中更改实体容器。动作引发的新规则最早在下一轮检测生效，避免同一步无限递归。

规则按优先级和稳定顺序确定结果。对同一目标的冲突设置动作在启动前告警；力源默认叠加，替换速度等写操作使用明确优先级。给动作队列、规则数、实例数设置预算并报告超限，禁止静默丢弃。

## 当前代码接入点

- `TransformTransformer`：坐标转换；需覆盖所有调用路径及逆向写回，不能只给某个 worldRoot 加 scale。
- `SimulationViewport.qml`：仿真器与播放器共用相机、网格和渲染视口。
- `EditorUnit.qml`：独立编辑器 View3D、Gizmo 叠加视图，以及时间轴占位区。
- `EditorManager`：根级场景配置必须参与保存、撤销、重做、多文档切换，不能仅保存在 QML 属性中。
- `SceneRecord` / `WorldSceneManager`：规则配置、生命周期、活动状态及安全边界执行。
- `Solver`：统一状态采样、接触事件收集与调度，实时及离线使用同一执行器。
- EPSX：记录动作事件、实体活动状态与动态实例信息，保证回放一致。

## 实施顺序和验收

1. 参考尺度、逆变换和质点标记；验证厘米、米、千米及自定义尺度下物理结果不变，拾取、拖拽、网格和导出一致。
2. 原生规则执行器及 JSON 校验；先完成时间点、区间、标量阈值、布尔组合、恒力和实体停用。
3. 中文规则卡片替换占位；补齐保存、撤销、多文档和对象删除引用校验。
4. 接触、休眠、滞回、事件延时及暂停；验证不同步长下触发误差与已声明语义一致。
5. 模板实例化及文件格式支持；验证实时、离线、回放一致。

性能基准分别测量规则编译时间和每步规则开销，覆盖 10、100、1000 条规则，避免以 GUI 帧率掩盖每步开销。物理回归必须覆盖已有弹性碰撞、摩擦、约束与休眠场景。
