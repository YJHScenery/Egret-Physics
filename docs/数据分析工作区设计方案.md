## 1. 目标与非目标

**目标**

1. 打开一个 `.epsx` 文件，列出其中所有可分析的实体与数据通道，允许用户勾选
   「一个或若干个实体的一项或多项数据」。
2. 允许用户指定二次抽帧步长（每 1 帧 / 2 帧 / 任意 N 帧取一个样本）。
3. 提供四类分析能力：
   - a) 把抽取结果**原样**写成 xlsx（对齐实时仿真器已有的导出格式）；
   - b) 散点图；
   - c) 线性 / 多项式 / 三角函数 / 指数 / 对数拟合；
   - d) 与用户给定的理论方程做误差对比，量化仿真模型精度。
4. 全部能力落地为「数据分析」工作区。

**非目标**

- 不生成、不修改、不重新采样 `.epsx` 文件（数据只读）。
- 不修改实时仿真器与离线求解器的行为（只在 b/c/d 中复用它们的既有实现思路）。
- 不做三维可视化（三维仍由「播放器」工作区承担）。

## 2. 数据源：EPSX 里到底有哪些数据

### 2.1 读取器已经具备的能力

`egret::epsx::EpsxReader` 已经提供本功能所需的全部读取能力，**无需改动格式**：

| 接口 | 用途 |
|------|------|
| `open(errorMessage)` | 校验文件头 / SCNE / INDX，失败时给出中文原因 |
| `sceneJson()` | SCNE 块的原始 JSON（实体清单、形状参数、求解配置） |
| `metadata()` | 采样间隔、抽帧比、声明帧数、生成者 |
| `frameCount()` | 实际可读帧数 |
| `sampleIntervalNs()` | 相邻帧的时间间隔（纳秒） |
| `readFrame(i, &frame, err)` | 读取第 i 帧的全部 BODY / CONS / FLDS 记录 |
| `readBody(i, slot, &body, err)` | 只读某槽位的刚体记录（抽取时用它减少解码开销） |
| `hasTrailer()` | 是否正常收尾（未收尾文件仍可读已完整写入的帧） |

### 2.2 可抽取的通道

`SCNE` 的 `entities[]` 给出稳定 ID、槽位、**名称**、质量、恢复系数、是否固定；
`models[]` 给出形状类型与尺寸参数。帧内可用字段如下。

| 类别 | 通道 | 来源 | 说明 |
|------|------|------|------|
| 公共 | 时间 $t$ | 帧头 `simTimeNs` | 单位 s；也是散点图默认横轴 |
| 公共 | 帧号 / 步号 | 帧头 `frameIndex` / `stepIndex` | 辅助横轴 |
| 刚体·直接 | 位置 $x,y,z$ | `BodyState.position` | m |
| 刚体·直接 | 姿态四元数 $x,y,z,w$ | `BodyState.rotation` | 无量纲，可派生欧拉角 / 转角 |
| 刚体·直接 | 线速度 $v_x,v_y,v_z$ | `BodyState.linearVelocity` | m/s |
| 刚体·直接 | 角速度 $\omega_x,\omega_y,\omega_z$ | `BodyState.angularVelocity` | rad/s |
| 刚体·直接 | 质量 $m$、恢复系数 $e$ | `BodyState.mass` / `restitution` | kg / 无量纲 |
| 刚体·直接 | 状态标志 | `BodyState.stateFlags` | 休眠 / 碰撞 / 积分 / 静态 |
| 刚体·派生 | 位置模长 $\lvert\vec r\rvert$、速率 $\lvert\vec v\rvert$、角速度模长 $\lvert\vec\omega\rvert$ | 向量求模 | |
| 刚体·派生 | 姿态欧拉角（roll/pitch/yaw） | 四元数 → 旋转矩阵 | rad |
| 刚体·派生 | 平动动能 $\frac12 m\lvert\vec v\rvert^2$ | 上式 | J |
| 刚体·派生 | ~~转动动能 $\frac12\vec\omega^\mathsf{T} I_{world}\vec\omega$~~ | **当前文件无法还原**：离线求解器写出的 `SCNE.entities[]` 只含 id/slot/name/mass/restitution/fixed，没有形状参数，算不出惯性张量 | v1 不提供，见 §8 R-01 |
| 刚体·派生 | 重力势能 $mg\Delta h$ | 需 `FLDS` 中的重力场；缺失时不提供 | J |
| 约束 | 标称长度 / 当前长度 / 误差 / 力大小 | `ConstraintState` | 单位随约束类型 |
| 约束 | 关联实体 A / B | `ConstraintState.entityAId/entityBId` | 用于命名「A–B 之间的弹簧」 |
| 力场 | 类型 / 启用标志 | `FieldState.type/flags` | 有效 |
| 力场 | 场矢量 / 场中心 / 场强 | `FieldState.vector/center/strength` | **当前写出端恒为 0**，见下 |

> **重要现状提醒**：按现行编码规范 §5.4 / §5.5，`CONS` / `FLDS` 的锚点、矢量、场强等
> 字段**尚未从模型层采集，写出值为 0**。因此 v1 的界面上，这些通道要么不出现，
> 要么显示但标注「该文件中未采集」。方案默认：**显示 + 置灰 + 悬停说明**，
> 用户能理解"文件里有这个段，但没存有效数据"，而不是困惑于全 0 曲线。

### 2.3 时间轴与采样语义

EPSX 的帧是等时间间隔的：第 $n$ 帧对应 $t_n = n \times \text{sampleIntervalNs}$。
因此

- 横轴默认取时间 $t$（秒），也可切换为帧号；
- 抽帧后仍然等间隔，只是间隔变成 $s \times \text{sampleIntervalNs}$；
- 滤波、FFT 之类的等间隔假设成立（三角拟合的频率估计会用到）。

## 4. 详细设计

### 4.1 抽帧（二次采样）

- 用户输入两种等价形式之一：**抽帧比** $s$（每 $s$ 帧取 1 帧）或**目标时间步** $\Delta t$；
  两者换算 $s = \operatorname{round}(\Delta t / \text{sampleIntervalNs})$，取 $s \ge 1$。
- 界面上再给 1 / 2 / 5 / 10 四个快捷档。
- 抽取时对 $k = 0,1,2,\dots$ 只读取第 $ks$ 帧；$\text{样本数} = \lfloor (\text{frameCount}-1)/s \rfloor + 1$。
- 抽取在后台线程执行，提供进度与取消（复用 `SimulationExportController` 的模式）。

### 4.2 xlsx 导出（"原封不动"）

目标是与实时仿真器 `SceneManagerViewModel::saveTrackingXlsx` 的输出**列结构一致**，
使两份数据可以直接比较。

| 场景 | sheet 布局 |
|------|-----------|
| 单实体 | 单 sheet：`时间` + 各选中通道各一列（向量拆成 x/y/z，另给模长列） |
| 多实体 | 每个实体一个 sheet，sheet 名 = 实体名（重名时追加 ID） |

表头使用与实时导出相同的中文列名与单位（`位置-x/m`、`速度-标量/m·s⁻¹`、
`角速度-x/rad·s⁻¹`、`动能/J` …），并加粗。表头行下方可选追加一段
「数据来源」块：epsx 路径、生成者、采样间隔、抽帧比、样本数。

导出同样在后台线程执行，写盘前先写临时文件再原子替换，避免半截文件。

### 4.3 散点图

#### 4.3.1 后端选型：Qt Graphs

**结论：用 Qt Graphs 2D**（`import QtGraphs`，本机 Qt 6.9.3 已安装，`Qt6::Graphs`）。
它是 Qt 官方为替代 Qt Charts / Qt Data Visualization 推出的模块，Qt Charts 已被标记停用，
Qt Graphs 则是官方长期维护方向；2D 部分基于 Quick3D/RHI，GPU 加速，QML 原生，
不与现有架构冲突，也不新增第三方代码。

本机 Qt 6.9.3 的 Qt Graphs 已验证具备本次所需的全部 2D 能力：

| 能力 | Qt Graphs API | 备注 |
|------|---------------|------|
| 绘图区 | `GraphsView { axisX; axisY; seriesList }` | QQuickItem，可 `grabToImage` 导出 PNG |
| 散点 / 折线 / 平滑线 | `ScatterSeries` / `LineSeries` / `SplineSeries` | 可多序列叠加 |
| 坐标轴 | `ValueAxis { min; max; tickInterval; subTickCount; labelFormat; labelDecimals }` | |
| 缩放 / 平移 | `zoomStyle` / `panStyle` / `zoomSensitivity` / `zoomAreaEnabled` | 内置交互，无需自绘 |
| 主题 | `GraphsTheme` | 可与 `DeepBlueTheme` 对齐配色 |
| 大数据量喂入 | `XYModelMapper { series; model; xSection; ySection; first; count }` | **从 `QAbstractItemModel` 直接取数，不逐点建 QML 对象** |

> **已知缺口**：Qt Graphs 6.9 没有 2D 对数轴（只有 3D 的 `LogValue3DAxisFormatter`）。
> 处理办法：需要对数显示时，在 C++ 侧对数据取 $\log_{10}$ 后再画，轴标签写成
> 「log₁₀(通道名)」，并在图上标注。这是数据变换，不是自绘图表。

架构上仍然沿用 `GraphsView` 的 QML 结构：

```
GraphsView
 ├─ ScatterSeries(实测数据)      ← XYModelMapper 绑定 C++ 的 LOD 模型
 ├─ LineSeries(拟合曲线 / 理论曲线) ← XYModelMapper 绑定分析结果模型
 ├─ ValueAxis (X / Y)
 └─ GraphsTheme
```

#### 4.3.2 大数据量下的绘图方式

绘图后端只负责画「屏幕上看得见的点」，不负责持有全量数据：

1. 全量序列以列式数组（SoA）保存在 C++ 侧（见 §4.6），绘图区拿到的永远是一份
   **按当前视口抽稀后的视图**（每像素列取 min/max，约为绘图区宽度的 2 倍个点）。
2. 用户缩放 / 平移后，C++ 用视口范围重新查询 LOD，重建几十 KB 的模型，绘图区刷新。
   于是无论原数据是 5 万点还是 500 万点，序列点数始终维持在 $O(\text{像素宽度})$。
3. 界面明确提示「当前显示：抽稀 N 倍（每像素 min/max）；拟合与导出使用全量 M 个样本」，
   并提供一个「查看全量散点」开关（全量模式下限制最大点数并给出性能警告）。
4. 悬停读数（crosshair）用时间列上的二分查找定位原始样本，读的是全量数据，不是抽稀后的值。

这样选型的重点就从「哪个库能画 100 万点」变成「谁能长期维护、交互与主题是否够用」，
Qt Graphs 在这两点上优于第三方库。

### 4.4 曲线拟合

统一形式 $y = f(x;\boldsymbol\theta)$，最小化 $\sum_i \bigl(y_i - f(x_i;\boldsymbol\theta)\bigr)^2$。

| 模型 | 形式 | 求解方式 |
|------|------|----------|
| 线性 | $y = ax + b$ | 线性最小二乘（QR / SVD） |
| 多项式 | $y = \sum_{k=0}^{n} a_k x^k$ | 线性最小二乘；$x$ 先归一化 $(x-\bar x)/\sigma$ 保证数值稳定 |
| 对数 | $y = a\ln x + b$ | 线性最小二乘（令 $u=\ln x$）；要求 $x>0$ |
| 三角函数 | $y = a_0 + \sum_{k=1}^{n}\bigl[a_k\sin(k\omega x) + b_k\cos(k\omega x)\bigr]$ | $\omega$ 给定 → 线性最小二乘；$\omega$ 未知 → 先 FFT 估计主频，再 LM 精修 |
| 指数 | $y = a\,e^{bx}$（可选 $+c$） | 无偏移：对数线性化；带偏移 $c$：LM 迭代 |

**非线性求解**用 Eigen 自带的 `unsupported/Eigen/NonLinearOptimization`
（`Eigen::LevenbergMarquardt` + `Eigen::NumericalDiff` 数值雅可比）。
它是 Eigen 仓库的一部分（MPL-2.0，与现有依赖同一份、同一许可），因此**不新增第三方库**。

输出：

- 系数表：符号表达式 + 数值 + 标准误；
- 拟合优度：$R^2$、调整 $R^2$、RMSE、MAE、最大绝对残差；
- 残差数组（用于残差子图）；
- 失败时的明确原因（迭代不收敛、样本过少、$x\le 0$ 与对数冲突、病态矩阵等）。

其中

$$R^2 = 1 - \frac{\sum_i (y_i-\hat y_i)^2}{\sum_i (y_i-\bar y)^2},\qquad
\mathrm{RMSE} = \sqrt{\frac1N\sum_i (y_i-\hat y_i)^2}.$$

拟合结果可以一键「作为理论方程送入误差对比面板」。

### 4.5 误差对比（理论方程 vs 仿真数据）

1. 用户在表达式编辑框输入理论方程，例如
   `x0 + v0*t + 0.5*a*t*t`、`A*sin(omega*t + phi)`、`C*exp(-lambda*t)`。
2. 自变量可取时间 $t$ 或任意已抽取的通道；常量/参数在下方「变量表」里赋数值，
   也可以直接引用上一步拟合得到的系数。
3. 逐点计算理论值 $\hat y_i = f(x_i)$，残差 $r_i = \hat y_i - y_i$，输出：
   - $R^2$、RMSE、MAE、最大绝对误差；
   - 归一化 RMSE：$\mathrm{NRMSE} = \mathrm{RMSE}/(\max y - \min y)$（避免除零）；
   - 相对误差（$y\ne0$ 时）的均值与最大值；
   - 一句结论式摘要，例如「平均相对误差 0.8%，最大绝对误差 3.2×10⁻³ m」。
4. 图表里同时叠加理论曲线与残差子图，并提供「导出对比表到 xlsx」。

表达式解析用 **muparser 2.3.5**：支持 `sin/cos/tan/asin/...`、`exp/log/ln/log10`、
`sqrt/pow/abs/min/max`、常数 `pi/e`，变量用 `DefineVar` 绑定。解析失败时
muparser 会给出错误码、出错位置与表达式片段，界面上直接在输入框对应位置高亮提示。

**可选增强**：把理论方程里的待定常数当作拟合参数（复用 §4.4 的 LM），
即"给定函数形式、由数据定参数"，再输出误差指标。默认关闭，避免与用户显式输入冲突。

### 4.6 大数据量：数十万到数百万样本怎么办

EPSX 的帧是等间隔的，一次 60 s、采样间隔 1 ms 的仿真就有 6×10⁴ 帧；长时长或小采样间隔场景
很容易到 10⁶ 帧，而每个实体每帧就有十几个可用标量。所以「先全部读进 QVariant / QML 对象」
这条路必须排除。处理办法分四层。

**第一层：抽取时只解码需要的槽位，边读边转列式存储**

- 用 `readBody(frame, slot)` 只解码被勾选的实体槽位，不构造完整 `FrameState`；
- 存储用列式数组（SoA）：每个「实体 × 通道」是一个连续的 `std::vector<double>`，
  而不是每帧一个结构体对象。这样后续抽稀、拟合、画图都是连续内存的顺序访问；
- 需要多少个点就先算出来给用户看：样本数 × 通道数 × 8 B，超过阈值时提示。

| 规模 | 单实体 12 通道占用 | 说明 |
|------|-------------------|------|
| 10⁵ 帧 | ≈ 9.6 MB | 常规，直接常驻内存 |
| 10⁶ 帧 | ≈ 96 MB | 单实体尚可，多实体需预算 |
| 10⁷ 帧 | ≈ 960 MB | 必须落盘映射，不能常驻 |

**第二层：超阈值时落到临时缓存文件 + 内存映射**

- 当 `样本数 × 通道数 × 8 B` 超过阈值（默认 256 MB，可配置）时，
  列式数据写入临时缓存文件，用 `QFile::map()` 建立只读内存映射按需访问；
- 缓存按「epsx 路径 + 文件修改时间 + 选择集 + 抽帧比」做哈希命名，
  命中即可秒开；退出时清理，不污染用户目录；
- 读取器已有的 `frameCount` / `simTimeNs` 足以在抽取阶段就建立时间列与索引，
  不需要二次遍历。

**第三层：多分辨率 min/max 金字塔（LOD）**

- 每个通道在列式数据之上建立分级摘要：第 0 级是原始样本，
  第 $k$ 级把 $1024^k$ 个原始样本归并成一个 $(min, max)$ 对；
- 建塔是 $O(N)$ 的一次性开销；1M 样本的一个通道总摘要约 16 KB，可忽略；
- 查询某个 $x$ 区间时，按区间跨度选择合适层级，再对每个像素列取 min/max，
  得到不超过约 $2\times$ 绘图区宽度的点集，直接交给 `XYModelMapper`；
- min/max 抽稀保留信号的包络（尖峰不会被抹掉），是示波器 / 波形编辑器的标准做法，
  比等距抽样更适合物理量的瞬态分析。

**第四层：分析与导出始终使用全量样本，只有"看"才抽稀**

- 拟合、误差对比、统计指标、xlsx/CSV 导出全部走原始列，不受 LOD 影响；
- 拟合前的样本量本身也是风险（10⁶ 点做 LM 迭代），策略是：
  先做 **均匀降采样** 拟合初值（如 2×10⁴ 点），再用全量样本做一次精修；
  线性最小二乘对 10⁶ 点本身就是毫秒级，无需特殊处理；
- 导出方面，QXlsx 是「整本工作簿驻留内存」的实现，10⁶ 行 × 10 列（10⁷ 单元格）
  会非常慢且吃内存。方案：
  - 默认上限 2×10⁶ 单元格，超出时提示；
  - 超大导出改走 **CSV 流式写出**（逐行落盘，内存恒定，Excel 可直接打开）；
  - 两种导出都在后台线程执行，带进度与取消，先写临时文件再原子替换。

### 6.1 为什么不用 Python 做交互绘图

本机确实具备条件：Anaconda Python 3.14.6 + matplotlib 3.11 + numpy/pandas/scipy + PySide6 6.11。
但把 Python 接进本程序的**交互**绘图会同时踩三个坑：

1. **Qt 版本冲突**：PySide6 是 Qt 6.11，本程序是 Qt 6.9.3。在同一进程内同时加载两套 Qt
   会符号冲突，属于不可接受的稳定性风险；只加载 matplotlib 的 Agg 后端可以绕开，
   但那样只能得到静态图片。
2. **性能不对等**：matplotlib 是纯 CPU 光栅化，10⁶ 点画一张图约 0.5–3 s，
   缩放/平移要整张重画，无法做到流畅交互；而 Qt Graphs + LOD 方案每帧只画
   $O(\text{像素宽度})$ 个点，是数量级的差距。
3. **部署成本**：一旦交互绘图依赖 Python，发行包就必须附带解释器 + 科学计算栈，
   体积和部署复杂度都显著上升。

**结论**：交互绘图用 Qt Graphs；Python 不进入主程序。如果将来确实需要出版级图形
（期刊插图、批量脚本分析），正确的做法是**独立的外部脚本**：主程序把抽取结果写成
CSV/Feather，用户自行用仓库里附带的 Python 脚本渲染，主进程不加载解释器。

## 8. 风险与待定项

| 编号 | 事项 | 影响 | 建议 |
|------|------|------|------|
| R-01 | 转动动能需要惯性张量 | 无法从现有文件还原 | 已核实：`OfflineSimulationRunner` 写出的 `SCNE.entities[]` 只有质量、没有形状参数，`models[]` 只存在于编辑器场景 JSON 中。故 v1 **只提供平动动能**；若确需转动动能，属于 EPSX 格式扩展（在 BODY 保留字段写 $(E_k^{trans}, E_k^{rot})$，向后兼容），单独作为一个需求评估 |
| R-02 | `CONS`/`FLDS` 的锚点、场矢量、场强目前写出恒为 0 | 这些通道无分析价值 | 界面显示但置灰并说明；是否顺带补全写出端属另一需求，不在本次范围 |
| R-03 | 超长仿真的点数（10⁶–10⁷ 级） | 内存与 I/O 压力 | 列式存储 + 超阈值落盘映射；min/max LOD 保证绘图恒定开销；导出改 CSV 流式（见 §4.6） |
| R-04 | 多项式阶数过高 → 病态 | 系数不可信 | 归一化 + 阶数上限 + 条件数告警 |
| R-05 | 三角拟合频率未知 | 收敛到局部极小 | FFT 主频作为初值 + 允许用户手动指定 $\omega$ |
| R-06 | Qt Graphs 为 GPLv3 | 与本项目 GPLv3 一致，但需确认团队接受该模块 | 若需完全避开 GPL 模块，退路是 QCustomPlot 桥接（同样 GPLv3）或外部 Python 脚本导出 |
| R-07 | 界面文案中英混排 | 一致性 | 沿用现有工作区风格（中文标题 + 英文副标题） |
| R-08 | Qt Graphs 2D 较新（Qt 6.6 引入，6.8/6.9 仍在演进） | 偶发渲染/交互缺陷 | P0 先做最小页面自检（加载模块 + 多序列 + 缩放）；把绘图封装在一个 QML 组件内，万一需要替换后端只改这一处 |
| R-09 | Qt Graphs 6.9 无 2D 对数轴 | 对数显示不可用 | 数据取 $\log_{10}$ 后绘制并把轴标注为 log₁₀（§4.3.1） |
| R-10 | QXlsx 整本文档驻留内存，超大表导出慢 | 千万单元格级导出不可行 | 2×10⁶ 单元格上限提示 + CSV 流式导出兜底（§4.6） |
| R-11 | 本机不允许擅自构建项目 | 我无法编译自验 | 代码按现有风格与 API 严格对齐；由你构建后按日志反馈迭代 |

## 9. 已确认的决策

1. **绘图后端 = Qt Graphs**（Qt Charts 的官方替代，本机已装，GPLv3，QML 原生，GPU 加速）；
   不嵌入 Python 做交互绘图，Python 仅保留为将来可选的外部脚本导出方案。
2. **对数轴**：Qt Graphs 6.9 无 2D 对数轴，需要时取 log₁₀ 后绘制并把轴标注为 log₁₀。
3. **转动动能**：已确认现有 EPSX 无法还原（R-01），v1 只提供平动动能。
4. **大数据导出**：xlsx 上限 2×10⁶ 单元格，超出提示改用 CSV 流式导出（已实现）。
5. **绘图抽稀**：每条曲线默认最多 4×10³ 个绘图点，由 min/max LOD 按视口选取；
   拟合、误差对比与导出始终使用全量样本（已实现）。
6. **跨文件对比**：不做，接口保留扩展余地。
