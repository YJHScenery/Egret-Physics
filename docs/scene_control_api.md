# 场景控制接口

本轮实现模型层的 C++ 接口与谓词枚举后端，接入真实世界求解流程。尚未提供编辑器规则界面、规则 JSON 序列化、用户函数编译或机器码运行时。原有显示尺度需求不在本轮实现范围内。

## 与执行后端无关的契约

`control::Program` 只定义两个操作：`evaluate(Frame, CommandBuffer)` 与 `reset()`。

`Frame` 包含仿真时刻、当前步长、只读实体状态及上一计算步真实进入接触求解的实体对。位置、速度、角速度使用 SI 单位，实体通过稳定 ID 标识，不向程序暴露引擎指针。物体数组按 ID 排序，接触对按较小 ID、较大 ID 排序并去重，以二分查找访问。

`CommandBuffer` 是有容量限制的动作输出，默认最多 1024 条。超限明确报错。判断程序不得修改输入快照或持有其视图到下次调用。程序实例由一个世界独占，按顺序调用，不承诺线程安全。

未来机器码后端可以继承 `Program`：将快照映射到其 ABI 输入，调用编译函数，把返回动作写入缓冲。世界管理器不需要知道程序是否采用枚举、字节码或机器码。这里仅保证逻辑可替换；C++ 虚表、`std::span`、标准库类型与布局不作为稳定的外部机器码 ABI，也没有实现沙箱、编译器或机器码执行预算。

测试中的 `ArbitraryProgram` 使用自定义数学函数生成力指令，没有依赖谓词枚举，验证抽象接口允许任意判断逻辑。

## 枚举后端

`PredicateProgram` 接收规则列表。每条规则包含条件节点序列、动作列表和触发模式，最后一个条件节点是根。`All`、`Any`、`Not` 只能引用自身之前的节点，构造时拒绝循环和前向引用；因此运行时是有界的顺序求值，无需递归或逐步解析脚本。

原子条件支持：时间、位置、速度、角速度、相对位置、相对速度、相对角速度、距离、活动状态、休眠状态及接触状态。向量可选 X、Y、Z 分量或模长；相对量定义为第一实体减第二实体。比较支持小于、小于等于、大于、大于等于、带绝对容差的近似相等、区间内和区间外。区间采用左闭右开。

缺失实体的原子条件为假；非活动实体的运动、休眠和接触条件也为假，`Active` 可显式检查停用状态。`Not` 对其子节点的布尔结果取反，因此否定缺失实体条件会得到真，调用方需要存在性语义时应先结合 `Active`。非有限数值不能通过数值条件。

触发模式包括 `Once`（本次运行首次成立）、`Rising`（由假到真）和 `WhileTrue`（每个成立的计算步）。首次判断之前状态视为假。已经触发的 `Once` 规则不再进行条件计算。构造时校验阈值、区间、枚举、引用和动作数值，预分配条件计算与触发状态内存。

## 动作及步边界

当前动作：设置位置、设置速度、启停实体、设置持久控制力。

世界的每次有效 `tick(dt)` 在积分前完成：

1. 采样同一份状态，所有规则读取该快照。
2. 调用控制程序生成动作。
3. 校验整个动作批次，包括实体存在性、动作种类与数值有限性。
4. 按规则及动作输入顺序统一执行，刷新求解缓存后推进物理。

后面的设置动作覆盖同一属性的前面设置动作；不同实体的动作互不影响。一个动作不能让另一规则在同一轮看到新状态，从而避免遍历顺序造成级联触发。动作的参数校验失败时，不修改物理状态、不推进时间；后端自身的触发历史不保证回滚，失败后应修正配置并重置或重新安装程序。内存分配失败等运行异常不承诺事务回滚。

时间点和区间在求解步边界判断，不切分时间步；阈值跨越最多延迟一个当前求解步被检测。零、负值及非有限步长不执行控制程序或推进世界。

接触条件表示“上一计算步曾进入真实接触求解”，包括 CCD 子步冲击和持续支撑；它不是 AABB 重叠，也不保证是该步末尾仍然存在的接触。第一步之前的接触记录为空，因此初始贴合状态也在完成首步求解后才能被接触谓词检测。对于瞬时碰撞，使用上升沿检测可能把连续两步发生的碰撞看作同一段接触；需要精确的开始／结束事件时，应以后续事件 API 扩展此语义。

停用实体不会物理释放对象：保留位置、速度和 ID，但退出积分、碰撞、可见渲染及依赖该端点的双端约束。独立多目标约束继续对活动目标生效；同时具有实体身份的场源也随实体停用。重新启用不会绕过原有 `loadTime`，其速度和位置保持原值。当前没有永久删除、创建新实例、设置角速度或直接修改约束的动作。

`SetForce` 替换指定物体的控制力，不是在每步重复累加。同一控制层的后写值覆盖前写值，零向量取消；它与重力及场景已有的其它力源叠加。在安装控制程序时预先创建一个稳定的控制力场记录，之后改变力值不改变场表长度；Verlet 的每次力重算都使用当前控制力。

## C++ 用法

```cpp
// 在场景注册后、开始求解和写入 EPSX 静态表之前安装程序。
using namespace egret::control;
Predicate time;
time.kind = PredicateKind::Time;
time.comparison = Comparison::GreaterEqual;
time.lower = 1.0;

Rule pull;
pull.predicates = {time};
pull.commands = {{CommandKind::SetForce, boardId, {26, 0, 0}}};
pull.trigger = Trigger::Once;
world.setControlProgram(std::make_unique<PredicateProgram>(std::vector<Rule>{pull}));
```

离线调用方可设置 `OfflineSimulationRunner::Request::controlProgramFactory`。每次离线运行调用工厂创建独立程序，并在导出实体、场的静态表之前安装；控制程序初始化或求解异常会转为离线请求的错误信息。没有配置工厂的旧调用路径保持原行为。

规则配置尚未写入 EPSX 场景 JSON，当前文件可回放已记录状态，但不能仅凭文件恢复控制程序再次求解；调用方必须保留原程序配置与工厂。控制动作没有独立事件日志。

`resetControlProgram()` 清空触发状态、接触历史和控制力，不回滚物体位置、速度或启停状态。完整重跑应清空并重新注册初始场景后重新安装程序。`clear()` 会释放整个控制程序。把世界时间调回较早值也会重置控制历史，但不恢复物理世界，不能作为状态倒带使用。

## 验证

`EgretControlTests` 验证条件组合、相对量、接触与休眠、区间边界、三种触发、重置、非法参数拒绝、动作预算和非枚举后端替换。

`EgretContactTests` 加入真实 `WorldSceneManager` 集成检查：持久控制力的 Verlet 求值、定时激活、停用后的积分／碰撞标志、恢复、取消力、静态场表长度、无效动作批次不部分修改世界，以及实际接触反馈。原有物理回归继续运行。

```powershell
cmake --build build --config Release --target Egret_Control_Tests Egret_Contact_Tests Egret_Physics Egret_Editor_Tests
ctest --test-dir build -C Release -R 'EgretControlTests|EgretContactTests|EgretEditorTests' --output-on-failure
```
