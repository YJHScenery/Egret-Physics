# 可编程场景控制设计与商业化选型

更新日期：2026-11-07。状态：设计方案，尚未实施。本文根据用户控制需求、上一阶段工作记录与当前源码整理；不表示新增运行时已经实现，也不构成全项目依赖授权审计。

## 1. 目标与决策

用户能够通过变量、条件、循环、自定义函数及跨步状态实现任意控制算法，读取场景状态并输出场景干预。规则卡片、代码编辑器和未来 LLM 共用执行契约。每个场景都包含一段场景干预源码；编译是每次场景求解任务的一部分，可在用户任意使用时发起。每次请求都校验对应源码并按需编译，再创建本次执行实例；物理逐步推进时执行编译产物，不逐步解析源码或调用模型。

确定路线：受限 C → Clang/LLD → WebAssembly → Wasmtime/Cranelift 在场景求解任务中按需编译为本机机器码。使用 Wasmtime C API，由标准 C++ 封装生命周期；主项目继续使用 Windows、PowerShell、MSVC 与 CMake。新增核心不依赖 Qt 或 GPL 系列库，详见第 17 节。

优先复用成熟编译器、运行时和现有控制接口；编译与执行核心不使用 Qt，配置交换采用标准 C++ 数据结构与经许可核验的非 GPL 解析组件；不自建语言解析器、优化器、机器码加载器或 Agent 框架。固定资源下不追求严格数学意义的无限存储图灵完备，目标是通用控制结构与有界资源执行。

## 3. 实体目录与无分配访问

引擎内部可以使用实体指针；用户程序只接收稳定 ID、属性和能力描述。场景安装时创建 ControlCatalog，绑定 ID 到内部实体或槽位，运行期间返回只读视图。场景重建使绑定失效；以后支持动态增删时增加代次校验。

现有 getAllPhysicalEntities 等接口返回 vector，不能视为无分配枚举。新增目录缓存或调用方预分配缓冲接口，避免每步重建指针列表。目录涵盖刚体、场、约束，但仅声明实际支持的读写能力。

安装时声明状态依赖，默认只采集需要的实体及属性；支持显式订阅全部实体。运行时不按名称查找，动作校验与提交使用预绑定索引。缺失绑定在安装阶段报错。

Wasm 使用独立线性内存，首版批量复制输入，不承诺零复制。目标是宿主控制桥接层稳态不重复分配；用户模块可在固定容量内分配子块；整个求解器是否无分配需要另行测量，不能由此推断。

## 4. 语言与内存约束

受限 C 支持 double、整数、布尔值、固定数组、结构体、局部变量、状态变量、分支、循环、自定义函数和 SDK 数学函数。首版禁止递归、变长数组、直接访问宿主堆、任意指针转换与运算、用户函数指针、文件、网络、线程和系统调用。动态分配仅允许使用 SDK 管理的模块内存池。ABI 指针由包装层管理，用户通过索引和 SDK 访问对象。

通过 Clang AST 校验执行语言限制，不采用禁用词扫描。预处理头文件只允许 SDK 白名单，编译参数由宿主固定，编译在独立进程完成并限制时间与输出体积。产物还要校验导入、导出、内存、表、指令特性及体积。

内存策略更新为“固定总容量，允许内部子块动态分配”。Wasm 内存初始页数等于最大页数，不允许运行时扩大线性内存，不暴露宿主 malloc/free。布局包括输入、输出、用户状态、固定栈、临时池、持久堆和常量区。模块内分配器可编译进用户程序，避免逐次跨宿主边界。具体语义见第 12 节；这项决定替代早期完全禁止动态分配的方案。

输入复制到用户内存并不使其物理只读。宿主保留权威快照，并重新校验输出长度、区域边界、动作权限、目标与有限数值，避免信任被程序改写的输入或计数。

## 5. 接口演进

保留 Program 的 evaluate/reset，不新增会迫使旧后端改写的纯虚函数。新增下列职责，可先采用组合与包装实现：

- ProgramDescriptor：ABI 版本、绑定、订阅、动作权限、内存容量、动作预算、fuel 和调用计划。
- ControlProgramSpec：可持久化源码、参数、绑定、编译设置与版本。
- ControlScheduler：决定是否调用，在状态采集之前判断。
- WasmProgram：实例管理、数据打包、调用、trap 转换与动作解码。
- CompositeProgram：按稳定顺序组合现有规则与用户程序，共用动作总预算。

外部 ABI 采用固定宽度整数、float64、明确字节偏移和长度；ID 为 uint64，地址为 Wasm 内存偏移，不暴露宿主地址、Qt、Eigen 或 STL 类型。定义版本号、结构长度、容量、状态码和保留字段，拒绝不兼容版本。

输入包含仿真时间、物理步长、步序号、距离上次控制调用的仿真时长、状态和接触数据。控制周期与物理步长不同，不能混用。整纳秒时间优先沿用离线路径；其他路径须明确转换策略，不能假定当前 double 时间已经具备整数精度。

输出为有界动作数组。所有程序读取同一快照，合并后统一校验及提交；默认后写设置覆盖前写设置。当前 SetForce 替换同一控制层的实体力，不能宣称多个控制程序的力自动叠加。

## 6. 调度与时间语义

| 需求 | 执行策略 |
|---|---|
| 1 秒开始施力 | 到期调用一次 |
| 3 秒结束施力 | 单独安排结束动作 |
| [1,3) 内反馈控制 | 区间内按控制周期调用 |
| 等待位置／速度阈值 | 按检测周期采样 |
| 等待接触 | 订阅接触信息并明确消费语义 |

固定事件优先使用排序数组与游标；存在动态插入需求时才采用最小堆。没有到期调用时跳过快照构造。持久力不依赖程序持续调用，关闭入口不会取消力，结束清理必须独立调度。

优化不能改变 Rising 历史或丢失接触事件。当前接触表示上一物理步曾进入接触求解，不是精确开始／结束事件；低频控制若需要不漏事件，必须维护有容量限制的事件累计或序号机制。

首版沿用步边界触发，越过阈值后延迟不超过一个物理步；降低检测频率后按实际周期声明误差。精确时间需切分物理步，而离线采样依赖固定步长，作为独立后续功能处理。调度基于仿真时间，播放器不重新执行控制程序。

## 7. 执行预算、失败与力函数

每次调用设置 fuel、动作数量和内存预算；epoch 用于取消／超时辅助。fuel 提供确定性预算但有成本，按基准确定默认值。宿主 SDK 函数也必须有界，不能假定 fuel 可以中断任意宿主阻塞调用。

越界、预算耗尽、非法输出导致动作丢弃并终止本次求解，报告程序、源码位置、步序号和仿真时间。用户状态可能已变化，首版失败后要求重置重跑，不承诺完整事务回滚。reset 恢复用户程序初始状态；完整重跑仍须重建物理初始场景。

控制程序每个控制周期只更新一次状态。连续的弹簧、阻尼等状态相关力应使用独立无副作用力函数，由积分器重复求值；不能重复执行带状态控制程序。当前 SetForce 表示采样后保持的力，不能等同于 Verlet 各求力阶段重新计算的连续力。

## 8. 保存、缓存与 LLM

每个场景必须保存干预源码、参数、稳定 ID 绑定、调度、ABI、工具链设置及摘要。无干预需求也保存合法空操作入口；旧场景加载时补默认源码，现有枚举规则通过适配／代码生成纳入场景程序，保持原语义。EPSX 后续增加实际动作事件和程序来源，供诊断与重新求解；回放只使用记录结果。

缓存键包含源码、SDK、编译器、Wasmtime、CPU 特征和配置。对外交换以包含源码的场景为准，Wasm 可作为附带产物但不能替代必需源码，机器码作为可重建本地缓存；仅反序列化可信缓存，文件摘要用于一致性，不可单独作为可信来源证明。

LLM 最后接入，作为可替换前端：读取目录与 SDK、生成配置、调用校验／编译、按诊断修订。支持用户 API Key 和可配置服务端点。密钥保存在前端安全存储，不进入源码、场景、EPSX 或日志。核心无需模型服务或 Agent 框架。

## 10. 实施顺序与验收

1. 定义 ABI、目录、程序配置和调度契约，复用既有后端与 JSON 路径。
2. 最小 Wasmtime 接入，以手写 Wasm 验证状态输入、动作、固定内存与 trap。
3. 接入 Clang AST 限制、LLD 及编译诊断，提供 SDK 和受限 C 示例。
4. 补齐组合执行、持久化、事件诊断及缓存。
5. 根据需求增加纯函数力接口、更多动作和精确事件。
6. 最后接入 LLM 前端。

验收覆盖旧规则结果一致；定时恒力启停；低频控制步长正确；接触累计语义；重跑清零；非法输出无部分提交；越界、死循环、动作超限中断；程序失败后明确停止；多世界状态隔离；10／100／1000 条规则与不同实体规模的采样、复制、执行、提交耗时。控制层分配计数与物理求解器分开统计。

商业化验收：新增依赖与实际分发包逐项登记，保留许可证／NOTICE，商业许可覆盖实际版本、模块及分发模式，未授权组件不进入发行包。

## 12. 固定容量内的动态分配与受限 C SDK

复杂度判断：顺序分配低，固定对象池低至中，任意大小申请与释放中，自动扩容／压缩／垃圾回收高。采用成熟、经许可检查的分配器，不自行开发通用 malloc；具体库尚未选定。

| 区域 | 生命周期 | 分配策略 |
|---|---|---|
| 输入区 | 每次调用刷新 | 宿主按固定 ABI 写入 |
| 动作区 | 每次调用计数清零 | 固定容量追加 |
| 用户状态区 | 跨步保持，reset 恢复 | 显式状态根结构 |
| 临时池 | 调用开始清空 | 对齐后的顺序分配 |
| 持久堆 | 跨步保持，显式释放 | 固定 arena 内的成熟分配器 |

SDK 规划：temp_alloc、state_alloc、state_free，以及由 SDK 封装的有界动态数组。用户通过受控缓冲区操作，不开放任意地址算术。Clang AST 规则须允许 SDK 指针、类型与规定的索引访问，禁止越过该范围的转换；限制细则与分配 API 同时设计，避免“允许分配却无法使用返回值”。

临时池指针不可跨调用保留；持久内存可被状态根引用。普通内存申请失败返回明确错误或空值；不得返回部分初始化容器。动态数组扩容失败保留原数组。应用可按程序策略处理内存不足；非法内存访问、分配器损坏或未处理错误终止本次求解。不要把固定容量误称为不存在碎片问题。

Wasm 限制宿主地址访问，不自动防止模块内越界覆盖其他子块、重复释放和释放后使用。调试模式可增加分配记录、边界检查与毒化；发行模式仍校验动作，不将模块内部数据视为可信。

reset 首版优先重建模块实例并恢复参数和状态，重新初始化堆，避免残留全局变量或分配器状态。今后做检查点需保存线性内存、相关可变 globals 和调度等宿主状态；不能只保存用户状态根或机器码。

只允许在控制程序调用阶段修改持久堆；纯函数力求值不修改持久状态，临时空间每次力求值独立重置。分配器操作计入执行预算，测试最坏分配序列和碎片场景。

验收增加：对齐、零长度与大小溢出策略、容量耗尽、扩容失败保留数据、反复申请释放、堆碎片、跨步持久数据、多实例隔离、reset 恢复与失效临时指针诊断。分配接口的具体边界行为应在实现前固定。

## 13. 受限 C 与原生数据交换

受限 C 使用标准 C 计算结构，限制可用库、指针形式和宿主能力；不创造新语法。SDK 查询函数和动作追加函数可编译进模块并内联，避免每个属性访问都调用宿主。

数据流：原生对象 → 宿主采样 → 固定输入区 → 用户机器码计算 → 固定动作区 → 宿主验证 → 修改原生对象。用户所见指针只属于 Wasm 线性内存；机器码执行并不意味着可以解引用宿主地址。

内部保持两种身份：场景持久化使用稳定 ID，运行时使用绑定槽位／句柄。槽位减少查找；代次用于区分删除后复用的槽位。ABI 不传递 PhysicalEntity、RigidBody、Eigen、Qt 或 STL 对象。字段偏移、对齐、长度和数值单位由共享 ABI 定义与构建检查约束。

本轮所有查询读取同一原始快照，提交修改后再次查询也不会看到新值；用户可以用局部变量计算预期新状态。下次调用看到提交并推进物理后的状态。控制状态可以立即更新，但不能将其误当成宿主已完成修改。

## 14. 宿主实体增删改查

| 操作 | 用户侧 | 宿主侧与当前范围 |
|---|---|---|
| 查询 | body_get 等读取快照 | 已有位置、速度、角速度、活动与休眠；其他属性按需扩展 |
| 修改 | set_velocity、set_force、set_active 等动作 | 复用已实现动作；质量／形状等需新增语义明确的动作 |
| 添加 | spawn_body 提交模板与初始参数 | 尚未实现真正创建；首版用预创建实体激活 |
| 删除 | 停用或 destroy_body 请求 | 停用已实现；永久销毁尚未实现 |

修改属性必须通过对应原生接口维护唤醒、惯量、碰撞与缓存，不提供任意写内存或通用无约束字段赋值。模板预登记形状、质量、材质等配置，创建动作可携带位置、速度等初值。

真正创建采用请求标识关联结果：本次输出模板实例化请求，宿主安全提交，下一次输入返回请求标识、成功／失败与新句柄。未成功前不能当作实体使用。结果反馈独立于实体订阅；固定反馈缓冲必须能容纳已受理请求结果，不能静默丢弃。首次实现不支持同批次引用待创建对象，需配置的初值放入创建请求。

永久删除时先处理关联约束与引用策略，再从场景、碰撞结构与缓存移除，使句柄失效后释放对象；代次必须防止旧句柄访问新对象。删除／重绑定后要更新目录、订阅与权限，失效引用明确报错。

当前“完整校验后提交”的保证不自动覆盖未来创建中的宿主分配失败。引入增删前应预留资源或准备完整事务方案；不能承诺异常情况下无条件回滚。宿主创建实体的分配与用户模块子块分配互相独立。

EPSX 当前实体集合固定，因此真正增删需同步设计生命周期记录和文件读取／回放；在此之前用预注册实例池的激活／停用实现教学场景需求。

## 15. 独立编译进程与商业化补充

编译建议采用独立进程：输入源码与受控参数，输出 Wasm、诊断、退出码；每次求解请求都进入编译准备流程，缓存有效时复用产物，否则即时编译并缓存。编译器随应用部署或在首次求解前完成可用性配置，不能仅存在于开发机。进程启动与文件交换属于求解任务开销，不进入每个物理步。

## 16. 场景内源码与求解任务生命周期（最新需求澄清）

编译发生于产品实际使用期间，是场景求解的组成阶段，而非仅编辑器预处理、软件安装或开发者打包步骤。本文“安装控制程序”只指向当前世界绑定运行实例，不指安装应用。每个场景具有干预源码，LLM 只是可选的源码编辑入口。

统一任务流程：接收场景与求解参数 → 捕获不可变场景／源码版本 → 校验 → 查询编译缓存 → 必要时 C 编译为 Wasm → 必要时编译为本机代码 → 创建本次世界与独立程序状态并绑定 → 逐步求解 → 输出结果。具体只读初始化可前置，但物理推进必须在程序准备成功后开始，控制力记录等静态表须在写出前建立。

GUI、命令行、批量与离线求解共用此入口；Agent 试运行也提交同一种求解请求。编辑器可提前做编译诊断以改善体验，但正式求解不依赖用户曾点过“编译”，也不依赖 Agent 保存的产物 ID。

缓存只是优化。新机器、缓存清空、源码／SDK／编译配置变化时，仍能由场景源码重新构建。每次运行创建独立实例、初始化持久堆与状态；可共享不可变编译模块，不能共享用户可变内存。参数若仅运行时注入，不必重编译；影响生成代码或 ABI 时必须进入缓存键。

编译失败属于求解失败，返回源码诊断且不推进物理；编译阶段支持进度、取消和超时。GUI 使用后台任务，命令行可同步等待。编译耗时、缓存命中、实例准备和物理求解耗时分别报告，整体均计入求解任务。

用户可在任意使用时修改代码并发起新求解。正在运行的任务保持捕获版本；新代码用于下一次任务。当前需求不自动推导为步内热替换，若以后要求运行中切换，另设安全边界、状态迁移和失败恢复协议。

验收增加：未经过编辑器编译的场景可直接求解；每个场景均可取得源码；旧场景补默认入口；空缓存可重建；编译失败不启动推进；求解中编辑不污染旧任务；批量任务状态隔离；正式任务独立检查源码和缓存一致性。


## 17. 新增强制约束：核心流程不使用 Qt 或 GPL 依赖

本节优先于此前允许复用 Qt JSON 或隔离调用 GPL 工具的讨论。场景干预代码的配置解析、校验、编译、缓存、ABI 转换、实体绑定、调度和机器码执行核心，不使用任何 Qt 模块，也不引入 GPL、LGPL、AGPL 系列库或工具。Qt 即使具有商业许可证，也不进入该核心；进程隔离或付费授权不作为本流程引入上述依赖的例外。

禁止范围包含直接／传递链接、头文件引入、生成代码和随流程分发的辅助工具；实际编译产物所需的分配器、数学库和辅助运行库也须核验。LLVM／Clang／LLD 与 Wasmtime 仍为候选，最终按固定版本、构建选项和实际传递依赖确认，不将主许可证等同于完整依赖树已通过核验。

核心接口仅使用标准 C++／C ABI，例如 std::string、std::vector、std::span、固定宽度整数和自定义错误类型。不出现 QString、QJsonObject、QObject、Qt 信号槽、QProcess 或 Qt 容器。Windows 编译子进程由原生进程 API 封装；文件、线程、缓存与诊断采用标准库或经核验的非 GPL 实现。不得因复用现有接口而隐式链接 Qt。

现有应用的 Qt 界面与 JSON 加载路径留在外围适配层，将场景转换为核心的 SceneDefinition／ControlProgramSpec；核心不反向依赖适配层。Qt 界面只是调用方，命令行和非 Qt 宿主也能独立使用核心。已有 WorldSceneManager 及离线求解路径不能直接视为无 Qt 实现，应检查依赖并抽出边界；无需因此立刻重写整个现有 GUI。

构建上设置独立核心 target，不开启 AUTOMOC／AUTOUIC／AUTORCC，不链接 Qt。建立非 Qt 测试宿主，验证从场景定义、源码编译到控制动作输出的完整链路；检查 include、链接依赖与分发清单。完整物理求解接入若仍依赖 Qt，应显式列为待解耦，不得宣称整条求解流程已经满足约束。

现有 GUI 与 Agent 的 Qt 展示／网络适配只存在于外围；Agent 生成的源码仍进入同一个无 Qt、非 GPL 核心。本文只规定接口与依赖边界，尚未实施解耦或完成依赖审计。
