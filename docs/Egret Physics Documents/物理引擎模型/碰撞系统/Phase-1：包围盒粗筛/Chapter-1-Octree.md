## 1. 基本概念与算法目标

**八叉树（Octree）** 将三维空间区域沿三个轴的中点分割，每个节点最多产生八个子区域，再对非空区域递归划分。它通过空间局部性聚集附近物体，使查询可以跳过不相交区域。

与 BVH 按物体集合分组不同，八叉树首先规定空间分区，再决定物体归属。AABB 相交、包含和候选对保守性见 [[Chapter-0-BroadPhase]]。

### 1.1 符号与节点结构

| 符号 | 含义 |
| :--- | :--- |
| $Q_v=[\mathbf{l}_v,\mathbf{u}_v]$ | 节点空间单元，本文根单元为正方体 |
| $E_v$ | 直接保留在节点上的实体集合 |
| $T_v$ | 整棵节点子树包含的实体集合 |
| $C(v)$ | 非空子节点集合 |
| $L,D$ | 容量阈值、深度限制，根深度为零 |

节点保存空间盒、八个子节点索引及直接归属实体索引。**内部节点也可以存实体**，因此不能只查询叶节点。

### 1.2 归属策略

本章采用**单归属、跨界保留**：只有当实体整个 AABB 被某个子单元包含时，才向下分配，否则留在当前节点。每个实体只存一次。

$$
T_v=E_v\;\dot\cup\;\bigdotcup_{w\in C(v)}T_w
$$

点上的圆点表示这些实体索引集合互不重叠，不表示各实体几何彼此分离。

另一种做法是把跨界实体复制到所有相交子单元；这会增加存储和候选去重工作，本文及当前内核不采用该方案。仅按中心点下放、却仍使用空间单元作为后代包围盒，可能破坏包含关系，不能替代完整包含判定。

## 2. 空间划分的数学定义

### 2.1 根节点

先合并全部有效实体 AABB，得场景盒 $B_s=[\mathbf{l}_s,\mathbf{u}_s]$。令：

$$
\mathbf{c}_s=\frac{\mathbf{l}_s+\mathbf{u}_s}{2},\qquad
h=\frac12\max_k(u_{s,k}-l_{s,k})+\varepsilon
$$

根正方体取为：

$$
Q_r=[\mathbf{c}_s-h\mathbf{1},\mathbf{c}_s+h\mathbf{1}]
$$

其中 $\varepsilon>0$ 提供微小余量，并使退化场景有非零空间尺寸。矩形区域也可以按三轴中点八等分；取正方体是本章及当前实现的选择，而非八叉树的必要条件。

### 2.2 八个子单元

令 $\mathbf{m}=(\mathbf{l}_v+\mathbf{u}_v)/2$。用位向量 $\mathbf{b}=(b_x,b_y,b_z)\in\{0,1\}^3$ 标记子区域：

$$
[l_{\mathbf{b},k},u_{\mathbf{b},k}]=
\begin{cases}
[l_{v,k},m_k],&b_k=0\\
[m_k,u_{v,k}],&b_k=1
\end{cases}
$$

索引可以写为 $b_x+2b_y+4b_z$。各子单元内部互不重叠，但闭边界共享分割面。

若实体退化到分割面上，可能被多个闭子单元同时包含，应使用固定顺序选择第一个可容纳单元，确保单归属和确定性。根盒膨胀不能消除内部各级分割面上的所有边界情况。

## 3. 构建流程

### 3.1 初始化

收集有效实体和 AABB，建立与原始场景索引的对应关系。没有有效实体时返回空树。构造根正方体，以全部有效索引、根深度零开始递归。

### 3.2 递归划分

对实体索引集合 $I$、空间单元 $Q_v$ 和深度 $d$：

1. 创建节点，记录 $Q_v$。
2. 若 $|I|\leq L$ 或 $d\geq D$，把全部实体存入 $E_v$，终止。
3. 计算八个子单元。
4. 对每个实体，寻找完全包含其 AABB 的子单元；找到则放入该子组，否则放入 $E_v$。
5. 仅对非空子组递归构建，空子索引设为无效。
6. 返回节点索引。

容量 $L$ 是触发划分的阈值，**不是所有节点实体数的硬上限**。大量实体跨越分割面时，内部节点可保留远多于 $L$ 个实体；达到深度限制的叶子也可超过阈值。

若所有实体都留在当前节点，继续创建空子节点没有收益；如果全部进入同一子单元，则仍需深度限制控制递归。工程上还可增加最小单元尺寸作为停止条件，当前内核主要使用容量与深度限制。

### 3.3 不变量

构建后应满足：每个有效实体恰好归属一个节点；每个实体 AABB 被归属单元及所有祖先单元包含；所有非空子单元位于父单元内。只有这些关系成立，后续基于单元盒的剪枝才是保守的。

## 4. 候选对遍历

### 4.1 同一子树内的组合分类

对节点 $v$，其实体组合恰好分为四类：

| 类别 | 检测方式 |
| :--- | :--- |
| $E_v$ 内部 | 两两枚举，每对一次 |
| $E_v$ 与某个子树 $T_w$ | 实体对节点查询 |
| 同一个子树内部 | 递归自碰撞 |
| 不同子树之间 | 对每个无序子节点对执行子树互查 |

每个实体对最终执行实际 AABB 相交测试后再输出规范索引对。不能因为两个实体处于同一节点就认定它们的 AABB 相交。

### 4.2 实体对节点查询

记 $\operatorname{queryEntity}(i,v)$：

1. 若 $B_i\cap Q_v=\varnothing$，返回。
2. 将实体 $i$ 与 $E_v$ 中每个不同实体进行 AABB 测试。
3. 对所有非空子节点递归查询。

这个操作覆盖父节点的大物体与任意深度的小物体之间的组合。

### 4.3 两棵不同子树互查

记 $\operatorname{queryPair}(u,v)$，其中两棵子树不共享实体。完整流程为：

1. 若 $Q_u\cap Q_v=\varnothing$，剪枝。
2. 测试 $E_u\times E_v$ 中的实体 AABB。
3. 对 $E_u$ 中每个实体，与 $v$ 的每个子树执行实体查询。
4. 对 $E_v$ 中每个实体，与 $u$ 的每个子树执行实体查询。
5. 对 $C(u)\times C(v)$ 的每个子节点组合递归互查。

此流程同样覆盖叶子与内部节点、两个叶子等情况，因为叶子的子节点集合为空。

**闭边界不能忽略**：兄弟空间单元内部不相交，但可以共享分割面。若物体恰好在该面接触，分属两侧子树的实体也必须进入候选。因此不能仅凭“不同八分区”就跳过所有跨子树检查。

### 4.4 完整性的直观说明

对任意实体对，若归属节点相同，则被局部枚举覆盖；若一个归属节点是另一个的祖先，则被实体对后代查询覆盖；否则二者有唯一最低公共祖先，在该祖先的不同子树互查中被覆盖。这三种关系穷尽全部情况。

若两实体真实相交，其祖先空间单元必不分离，因此正确包含不变量下的剪枝不会跳过它们。单归属和无序子节点对遍历同时避免结构性重复。

## 5. 复杂度、参数与适用场景

每个实体每层最多进行八次包含检查，深度上限为 $D$，缓存 AABB 后建树工作量可估为 $O(ND)$。稀疏分配时只建立非空节点；保守的节点数量上界为 $O(ND)$，并非必然分配完整的 $8^D$ 个单元。

查询成本取决于访问的节点对和局部实体对数量，最坏仍有 $O(N^2)$ 实体组合。大量大物体留在根节点时，空间划分对这部分几乎没有加速作用。

| 参数 / 场景 | 影响 |
| :--- | :--- |
| 较小的 $L$ | 更多节点与更细空间，可能减少局部枚举 |
| 较大的 $D$ | 更深层次与更多构建开销，不一定降低总耗时 |
| 大小接近、空间分散 | 通常有利于空间剪枝 |
| 大物体、细长物体、跨中心平面聚集 | 高层保留实体多，容易退化 |
| 远距离离群物体 | 根盒变大，其余物体可能集中在少数分支 |

动态场景可以每次重建，也可以维护物体归属并在越界时重新插入。松散八叉树用扩大的子单元减少移动时的迁移，但其子单元可以重叠，必须继续执行保守查询；这是扩展方案，当前实现并非松散八叉树。

## 6. 当前项目对应与实现边界

- 内核：`src/model/strategy/broad_phase_strategy/kernel/octree_kernel.h`。
- 适配：`src/model/strategy/broad_phase_strategy/octree_broad_strategy.cpp`。
- 默认容量为 8、最大深度为 6，终止条件使用 `depth >= m_maxDepth`。
- 每次调用 `build()` 清空并重建节点，缓存当前实体 AABB；根半尺寸增加 `1e-6`。
- 跨分界实体保留在父节点；普通实体对输出前检查实际 AABB，并将索引规范为小者在前。
- 适配层按快照顺序传入实体；它没有采用 BVH 适配层那样的 `enableCollision` 预过滤，不能假定两者过滤行为相同。

**阅读当前源码时的边界**：`traverseSelfCollision()` 已安排局部、祖先与后代、各子树自身及兄弟子树查询；但 `traverseNodeVsNode()` 的非叶分支主要继续对子节点递归，没有完整体现第 4.3 节中两侧内部节点保留实体的所有组合。因此本章第 4 节描述的是完整设计，不能据此直接宣称当前跨子树路径已满足全部完整性条件。

本文仅补充文档，不修改该实现。验证时应特别加入“不同子树、其中一侧或两侧内部节点保留跨界物体、分割面接触”的组合，并与暴力 AABB 基线比较。
