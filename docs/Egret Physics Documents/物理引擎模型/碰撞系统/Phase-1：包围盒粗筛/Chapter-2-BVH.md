## 1. 基本概念与算法目标

**包围体层次结构（Bounding Volume Hierarchy，BVH）** 把物体集合递归分组，并为每组建立包围其全部后代的包围体。本文采用二叉 AABB 层次结构：叶子存实体索引，内部节点保存左右子节点索引和合并包围盒。

```text
              场景合并盒
              /       \
          物体组甲     物体组乙
          /    \       /    \
        叶子   叶子   叶子   叶子
```

树上物体集合的分组互不重叠，**不意味着子节点包围盒互不重叠**。一个物体可以跨过分组时参考的空间平面，仍完整归入一个子组，由该组实际包围盒覆盖。

八叉树规定空间单元，BVH 则使包围盒适应物体分布。两者的基础数学与输出契约见 [[Chapter-0-BroadPhase]]。

### 1.1 符号与包含不变量

| 符号 | 含义 |
| :--- | :--- |
| $I_v$ | 节点 $v$ 的全部后代实体索引 |
| $v_L,v_R$ | 左右子节点 |
| $B_v$ | 节点的合并 AABB |
| $\mathbf{c}_i$ | 实体 AABB 的中心 |
| $L,D$ | 叶容量阈值和深度参数 |

内部节点满足：

$$
I_v=I_{v_L}\;\dot\cup\;I_{v_R},\qquad
B_v=\operatorname{merge}(B_{v_L},B_{v_R})
$$

叶节点满足 $B_i\subseteq B_v$，每个有效实体恰好归属一个叶子。本文的内部节点不直接保留实体，这与八叉树父节点保留跨界实体的模型不同。

## 2. 构建：最长轴与中位数划分

### 2.1 节点包围盒

对非空实体集合 $I$，按分量求极值得到：

$$
\mathbf{l}_v=\min_{i\in I}\mathbf{l}_i,\qquad
\mathbf{u}_v=\max_{i\in I}\mathbf{u}_i
$$

当 $|I|\leq L$ 或达到深度限制时，生成叶子并保存全部实体索引。空场景应在入口直接构造空树，不进入需要读取首个实体的递归函数。

### 2.2 选择排序轴

定义合并盒尺寸：

$$
\mathbf{e}_v=\mathbf{u}_v-\mathbf{l}_v,\qquad
k^*=\arg\max_{k\in\{x,y,z\}} e_{v,k}
$$

按实体 AABB 中心的 $k^*$ 分量排序：

$$
 c_{i,k^*}=\frac{l_{i,k^*}+u_{i,k^*}}{2}
$$

取 $m=\lfloor |I|/2\rfloor$，将排序后前 $m$ 个索引分配给左子树，其余分配给右子树。

**注意**：这是按元素数量二分，不是按空间中点划分。因此即使全部中心相同，只要当前集合至少有两个实体，仍然可以形成两个非空子组。相同键值时可额外按稳定实体标识排序，以提高构建结果的确定性。

### 2.3 递归流程

1. 合并当前全部实体 AABB，记录节点盒。
2. 检查容量与深度停止条件。
3. 选择最长轴，按盒中心排序。
4. 按中位数分为两个非空集合。
5. 递归构建左右子树。
6. 保存左右子索引，返回当前节点索引。

这类划分倾向于平衡实体数量，但不直接最小化包围盒重叠。极大物体、细长物体或相同中心可能造成左右盒几乎完全重合。

若使用数组存节点，递归添加子节点可能触发数组扩容，应以索引建立关系，避免跨递归持有可能失效的数组元素引用。当前内核先完成子树，再把父节点追加到数组，根节点不必位于索引零。

## 3. 自碰撞查询：节点对递归

### 3.1 为什么从根与自身开始

调用 $\operatorname{visit}(r,r)$，其中 $r$ 为根。节点对 $(u,v)$ 表示检查两个后代集合之间可能相交的实体对。若节点盒不相交：

$$
B_u\cap B_v=\varnothing
\Longrightarrow
\forall i\in I_u,j\in I_v:\ B_i\cap B_j=\varnothing
$$

于是可以立即返回。

### 3.2 两节点相同

若 $u=v$ 且为内部节点，只遍历：

$$
(v_L,v_L),\qquad(v_L,v_R),\qquad(v_R,v_R)
$$

不再遍历 $(v_R,v_L)$，否则会重复计算相同无序组合。

若为同一个叶子，只枚举该叶子索引列表中位置 $p<q$ 的组合，再将实体索引规范化为 $i<j$。列表位置顺序与实体编号大小是两个概念。

### 3.3 两节点不同

| 节点类型 | 操作 |
| :--- | :--- |
| 两个叶子 | 枚举两个叶子实体集合的笛卡尔积 |
| 左侧叶子、右侧内部 | 查询 $(u,v_L)$、$(u,v_R)$ |
| 左侧内部、右侧叶子 | 查询 $(u_L,v)$、$(u_R,v)$ |
| 两侧均为内部 | 查询左右子节点组成的四个组合 |

也可每次只展开较大盒的一侧，减少一次性分支数；继续展开后仍需覆盖全部必要组合。当前项目使用表中的递归形式。

### 3.4 叶级输出的两种语义

**方案一：逐实体 AABB 复检。** 仅当 $B_i\cap B_j\neq\varnothing$ 时输出。这样在相同过滤条件下，结果可与暴力 AABB 相交对集合一致。

**方案二：输出重叠叶子中的全部组合。** 只要叶盒相交，就把叶内全部组合交给窄相位。它仍是保守粗筛，但会多出实体 AABB 实际分离的候选。

例如一个叶子含有 $x$ 区间分别为 $[0,1]$ 和 $[9,10]$ 的两个物体，叶盒覆盖 $[0,10]$；另一个物体位于 $[4,5]$。叶盒重叠不能证明其中任何实际实体对重叠。

当前 BVH 内核采用第二种语义。叶容量越大，可能产生越多此类额外组合，不能把当前输出描述成“全部且仅有实际 AABB 相交对”。

### 3.5 完整性与去重

对任意两个不同实体，其叶节点若相同，会在该叶内枚举；若不同，则在两叶最低公共祖先的左右交叉查询中进入唯一的跨子树组合。祖先盒覆盖所有后代，因此真实相交对不会被正确的节点剪枝排除。

这个结论要求实现始终保持实体索引不变。生成规范对时，应对原始索引创建临时副本再取最小、最大，不能在嵌套循环内修改后续组合还要使用的外层索引。规范化 $i<j$ 与集合去重也不是同一件事。

## 4. 动态场景的维护方案

### 4.1 全量重建

每次候选查询前，从当前位姿重新计算包围盒并构造树。优点是状态同步直接、树布局重新适应场景；代价是重复构建与排序。当前项目采取此方式。

### 4.2 自底向上更新（Refit）

保持分组拓扑不变，更新叶盒后，从下往上合并左右盒。若缓存布局、每个实体出现一次，更新可在 $O(N)$ 工作量内完成。

Refit 保证包含关系，但不保证分组质量。物体长距离交换位置后，子树盒可能变大并重叠；可根据查询成本、重叠率或质量指标触发局部或全量重建。

### 4.3 动态 AABB 树与扩张盒

动态树支持插入、移除、重新插入及平衡。为实体保留略大的代理盒：

$$
F_i=[\mathbf{l}_i-\boldsymbol{\delta},\mathbf{u}_i+\boldsymbol{\delta}],\qquad
\boldsymbol{\delta}\geq\mathbf{0}
$$

实际 AABB 仍在代理盒内时，可暂不重新插入；越界时更新代理盒并调整结构。扩张越大，维护频率可能越低，候选误报可能越多。Box2D 官方文档将动态树描述为用于组织形状和空间查询的二叉层次结构，见 [Dynamic Tree](https://box2d.org/documentation/group__tree.html)。

扩张盒仅在覆盖整个运动区间时才可作为 CCD 扫掠盒。固定余量不天然保证覆盖高速运动。Refit、动态插入和平衡均为扩展方案，不能据此认定当前 `BVH` 已实现这些能力。

## 5. 扩展构建：表面积启发式

### 5.1 定义与代价模型

**表面积启发式（Surface Area Heuristic，SAH）** 用子盒表面积和实体数估计分割代价。三维盒边长为 $a,b,c$ 时：

$$
A(B)=2(ab+bc+ca)
$$

常见射线查询模型为：

$$
C_{\mathrm{split}}=C_t+
\frac{A(B_L)}{A(B_v)}N_LC_i+
\frac{A(B_R)}{A(B_v)}N_RC_i
$$

其中 $C_t$ 为节点遍历成本，$C_i$ 为单个几何测试成本，叶子代价为 $C_{\mathrm{leaf}}=NC_i$。可比较不同划分以及不划分的代价。该模型及分桶构建见 [PBRT：Bounding Volume Hierarchies](https://www.pbr-book.org/4ed/Primitives_and_Intersection_Acceleration/Bounding_Volume_Hierarchies)。

这个概率解释针对射线分布；碰撞粗筛查询的是盒对，不能直接把表面积比当作任意场景的真实相交概率。用于粗筛时应结合子盒重叠、实际节点访问数和候选数量评估收益。

### 5.2 分桶近似

1. 沿候选轴按中心坐标范围分桶。
2. 为每桶累计实体数和合并盒。
3. 用前缀、后缀合并计算各桶边界两侧的盒与数量。
4. 比较合法非空分割的估计代价，选择较优边界。
5. 中心范围退化、表面积为零或分割无效时，使用中位数分割或终止为叶子。

SAH 用更多构建工作换取潜在查询收益；是否优于简单中位数构建，取决于重建频率及查询负载。当前项目没有采用 SAH。

## 6. 复杂度与方案选择

当前实现在每个递归节点完整排序。平衡二分、AABB 获取按常数成本计时，建树递推近似为：

$$
T(N)=2T(N/2)+O(N\log N)
\quad\Longrightarrow\quad T(N)=O(N\log^2N)
$$

不能仅凭“树高为对数”就把这种重复排序构建写成 $O(N\log N)$。若使用期望线性时间的中位数选择并缓存 AABB，平衡构建的期望成本可降低到 $O(N\log N)$；这属于可选优化。

单归属二叉树的节点与实体索引存储为 $O(N)$。查询仍可能检查平方数量的组合，且显式输出 $K$ 对至少需要 $\Omega(K)$ 时间和 $O(K)$ 输出空间。对数树高不意味着所有场景的查询都是对数时间。

| 需求 | 可考虑的方式 |
| :--- | :--- |
| 实现简单、物体频繁大幅运动 | 中位数构建并重建 |
| 拓扑稳定、物体小幅移动 | Refit，并按质量退化触发重建 |
| 高频插入删除与局部移动 | 动态 AABB 树 |
| 构建次数少、查询次数多 | 评估 SAH 等较高质量构建 |

与八叉树相比，BVH 通常更容易适应不均匀分布及不同尺寸物体，但没有对所有场景都更快的保证。应比较建树耗时、节点访问、候选数和精确检测总成本。

## 7. 当前项目对应与实现边界

| 项目 | 当前实现 |
| :--- | :--- |
| 内核 | `src/model/strategy/broad_phase_strategy/kernel/bvh_kernel.h` |
| 适配 | `src/model/strategy/broad_phase_strategy/bvh_broad_strategy.cpp` |
| 默认参数 | 叶容量 8，深度参数 16 |
| 深度停止条件 | `depth > m_maxDepth`，与八叉树的 `>=` 有区别 |
| 划分 | 合并盒最长轴、实体 AABB 中心完整排序、数量中位数二分 |
| 更新 | 每次 `build()` 全量重建；没有持久 Refit 或动态代理维护 |
| 叶级查询 | 输出叶组实体组合，不进行逐实体 AABB 复检 |
| 适配层过滤 | 跳过关闭碰撞、空实体、空形状的条目 |
| 索引映射 | 用 `bodyIndices` 将紧凑树内索引映射回快照索引 |

当前不同叶子的笛卡尔积循环在规范化时会交换循环索引变量。理解本章第 3.5 节的契约时，应将其视为需要单独验证的实现边界，不能只根据递归结构就认定输出天然无漏项、无重复。本文不改动代码，也不替代运行验证。

验证可将规范候选集与暴力 AABB 基线比较：基线必须是候选集的子集，同时单独检查输出重复、非法索引及编号顺序。由于当前采用叶组输出，要求两个集合完全相等并不符合其输出语义。
