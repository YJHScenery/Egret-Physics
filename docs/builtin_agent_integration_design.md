# 内置 Agent 接入方案

日期：2026-11-07。状态：概念与接口设计，尚未实施。依赖 [可编程场景控制设计](programmable_scene_control_design.md)，在控制 SDK、编译器与执行器稳定后接入。不预设具体模型、价格或第三方服务的完整兼容性。

## 1. 目标与产品定位

用户以自然语言描述题目、时间条件和干预行为，Agent 读取当前场景及能力，生成规则或受限 C 控制程序，调用本地校验、编译和有界试运行，解释结果并交付可保存的配置。

Agent 是编辑前端，不是物理求解循环的一部分。断网、没有 API Key 或用户关闭 Agent 时，规则卡片、代码编辑和场景编译与求解仍可使用。每个场景保存干预源码。简单需求可以通过现有规则 UI 生成等价源码／规则适配入口，复杂需求直接生成受限 C；普通用户无需亲自编写代码。

## 2. 总体架构

```text
QML 对话与预览面板
        ↓
AgentSession／本地编排状态机
        ├─ ModelProvider：模型服务协议适配
        ├─ ContextBuilder：场景与 SDK 上下文
        ├─ SkillRegistry：领域说明与流程模板
        └─ ToolDispatcher：参数校验与领域工具执行
                    ↓
       编辑器草稿／编译服务／独立试运行
                    ↓
       可审阅配置 → 编辑器事务应用 → 保存
```

首版用一个有界的工具调用循环，无多 Agent、通用终端、任意脚本或远程 MCP 依赖。Qt 网络与 JSON 能满足首版协议桥接；新增网络模块的构建接入需在实现时确认，不声称当前目标已链接。

## 3. 服务与凭据

支持用户填写 API Key、服务端点、模型名称、请求超时和输出预算。官方 OpenAI 路径建议使用 Responses API 的 function calling；其他“OpenAI 兼容”服务按实际能力提供 Chat Completions 或其他适配，不能仅修改 URL 就宣称兼容。

统一内部消息、文本增量、工具调用、工具结果、结束原因、错误与 usage 格式。工具调用标识由适配层保留并正确关联；若服务不支持工具调用，退化为生成可校验草稿，不执行未结构化文本里的指令。

密钥由本地网络服务读取并发送到用户明确配置的端点，优先使用 Windows 凭据存储或受系统保护的本地存储。QML 只显示掩码；场景文件、程序源码、EPSX、对话导出和诊断日志不保存密钥。跨端点重定向不携带凭据；取消与错误日志脱敏。

发送前明确当前服务端点和上传内容范围，默认只发送当前任务所需场景摘要、选定源码及诊断，不上传整个工程、任意文件或完整仿真历史。独立的厂商产品授权与模型服务条款分别处理。

## 4. 领域工具最小集合

下列工具名为规划契约，不是当前已实现 API。所有输入有 schema，宿主校验类型、长度、引用、文档版本和资源预算，模型输出不获得额外权限。

| 工具 | 功能 | 执行位置 |
|---|---|---|
| get_scene_catalog | 获取实体 ID、名称、类型、单位与能力 | 当前编辑器快照 |
| get_scene_state | 查询选定对象的初始／指定记录状态 | 本地只读接口 |
| get_control_sdk | 获取指定版本语法、ABI、动作及示例 | 内置文档 |
| get_skill | 按任务获取领域流程说明 | 内置资源 |
| create_control_draft | 建立规则／代码及参数、绑定、调度草稿 | 独立草稿存储 |
| validate_control | 检查 schema、单位、绑定和能力 | 本地校验器 |
| compile_control | 调用受控编译服务，返回诊断与产物 ID | 独立编译进程 |
| trial_simulation | 对场景副本进行限时、限步试运行 | 后台独立世界 |
| get_trial_summary | 查询关键物理量、事件和运行错误 | 有界结果摘要 |
| propose_scene_patch | 生成可预览的场景配置变更 | 草稿事务 |

首版把“应用草稿”作为产品操作，调用已有编辑器事务与撤销机制。用户明确要求自动应用时可在授权范围内自动完成，无需每次工具调用弹窗；超出范围的永久删除、覆盖外部文件等另行处理。单次草稿内容、文档 revision 与编译产物摘要必须对应，避免应用未验证的新版本。

模型不直接访问 WorldSceneManager 指针，不修改运行中的求解实例，不绕过 CommandBuffer，不加载任意机器码缓存。创建、删除、修改实体只通过已支持的场景命令或运行期控制接口。

## 5. Agent 工作流

1. 捕获当前文档 ID、revision、用户目标和授权范围，获取必要目录与 SDK。
2. 整理对象绑定、SI 单位、时间区间、触发方式及需要的动作；歧义会改变物理含义时向用户澄清，其他采用可见假设。
3. 选择规则或代码，建立草稿及参数、内存与调用预算。
4. 本地验证。失败后把结构化诊断交给模型修订，修订轮数有上限。
5. 编译通过后按任务需要在场景副本试运行；不把编译成功当作物理正确。
6. 展示条件、动作、对象、持续时间、代码差异、试运行摘要与未验证项。
7. 按已有用户授权应用配置，写入一个可撤销编辑器事务。文档 revision 已变化时重新验证绑定与差异，不自动覆盖并发编辑。

示例：“1 秒时给木板向右 26 N，持续 2 秒”生成 1 秒设置力与 3 秒取消力两个事件；不会用停止调用控制器来代替取消持久力。若现有规则可表达，直接复用枚举后端。

## 6. 内置 Skills 的设计

这里的 skill 是本产品自己的版本化领域资源，不依赖 Codex／ChatGPT 的技能安装目录。首版采用 Markdown 说明、manifest 和现有 SDK 示例，按需载入；不是额外代码执行权限。

| 名称 | 内容 |
|---|---|
| scene_inspection | 单位、坐标、实体身份、场景约束及状态读取 |
| timeline_control | 区间、一次触发、边沿、持续力清理与检测误差 |
| control_programming | 受限 C、ABI、固定容量分配、错误处理 |
| physics_validation | 解析量对照、量纲、守恒适用条件和数值误差 |
| simulation_diagnostics | 编译诊断、运行 trap、预算与试运行报告 |

每份资源标明版本、适用 SDK、所需工具及预期交付物。可复用现有题目场景和文档，但只作为参考数据。场景名称、用户代码注释、导入文件和工具返回中的文本不能覆盖系统规则或授权范围。

## 7. 会话、异步与失败处理

本地状态机包括 Idle、Requesting、ExecutingTool、WaitingForUser、Completed、Failed、Canceled。网络和试运行不阻塞 GUI；工具结果回到所属会话，取消后不再执行新动作。文档切换不改变工具的绑定文档。

支持流式文本并展示“读取场景／校验／编译／试运行”等可观测进度。工具参数的流式片段必须组装完整并校验后才执行。读操作可并行，修改与依赖调用串行；首版可以全部串行以降低复杂度。

为会话设置模型轮数、工具调用数、编译次数、试运行步数与墙钟预算，达到上限交付已有草稿和明确状态。网络重试采用退避，只对安全可重试请求自动处理；有副作用工具用请求 ID 去重，不能因断线重复应用场景修改。usage 可展示，金额仅在有可靠模型价格映射时估算。

工具结果提供错误类别、错误码、源码位置及有限摘要。区分鉴权失败、服务不兼容、限流、编译错误、无效绑定、内存耗尽、fuel 耗尽和物理异常。涉及真实项目异常时，诊断流程遵循项目 AGENTS.md；试运行数据与正式世界、日志分开标识。

## 8. 接入现有工程

建议新增职责而非立即创建这些目录／类：

- AgentSession 与 AgentController：会话、取消、预算和 UI 状态。
- ModelProvider：协议适配、流式事件解析、错误归一化。
- AgentToolRegistry：schema 与领域能力分派。
- AgentContextBuilder：场景摘要、SDK 及 skills 按需获取。
- AgentDraftStore：源码、绑定、差异、诊断、版本和产物关联。

优先复用 EditorManager 的设置保存和撤销、多文档身份；复用控制配置、编译服务和 OfflineSimulationRunner。试运行必须建立独立世界与独立程序状态；源码内容不能在 GUI 线程临时编译。

## 9. 实施阶段与验收

1. 先把目录、草稿、校验、编译、试运行工具做成不依赖模型的本地接口。
2. 接入一个官方 OpenAI 服务适配器与最小工具循环，支持 Key、取消和错误。
3. 加入内置 skills、规则／代码选择、诊断修订和差异预览。
4. 加入授权范围内应用、撤销、多文档与断线恢复。
5. 按真实用户需求增加其他服务适配器；不预先建设插件市场或多 Agent 平台。

验收覆盖：无 Key 时手工流程可用；简单定时施力生成正确起止事件；复杂控制生成可编译程序；服务失败保留草稿；预算耗尽停止；错误不触发无限修订；取消不应用变更；并发编辑不被覆盖；试运行不污染场景；密钥不出现在保存／导出／日志中；工具不接受越权字段；生成说明不虚构试运行结果。

新依赖沿用主方案商业化政策：优先复用 Qt 与宽松许可库，按实际分发物登记许可证，不把服务收费或 SDK 免费等同于无限制使用。

## 10. 官方资料与边界

OpenAI 官方 function calling 描述了应用接收工具请求、执行本地工具并返回结果的多轮流程；本文的领域工具、状态机、skills 和授权方式是本项目设计，不是声称 OpenAI 自动提供这些本地能力。

- [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling)

具体请求字段和支持特性在实施时按选定服务、模型与官方文档确认，不固定模型名称或引用未经核实的价格。


## 11. 与求解期编译的关系（最新需求澄清）

每个场景包含干预源码，求解任务负责校验、按需编译、绑定与执行。编译不依赖 Agent 在线，也不要求用户先在编辑器里编译。Agent 的 compile_control 工具只用于提前反馈和修订，可预热缓存，不能代替正式求解中的编译准备阶段。

create_control_draft 和应用草稿必须持久化源码及绑定、调度和参数，不能只保存产物 ID。trial_simulation 提交包含源码的场景副本，经过与正式求解相同的校验和缓存处理；正式任务再次捕获当前版本并检查一致性。每次试运行和正式运行均创建独立状态。

应用仍需部署／配置可在使用期间工作的编译服务。Agent 面板分别展示生成、校验、求解期编译和物理推进，编译失败作为求解诊断反馈。用户在求解期间改写源码只影响后续任务，首版不承诺热替换正在执行的程序。


## 12. 无 Qt、非 GPL 核心的强制边界

场景源码的解析、校验、编译、缓存、绑定与执行统一进入主方案第 17 节规定的核心，不使用 Qt 或 GPL／LGPL／AGPL 系列库及工具；不能通过独立进程重新引入 GPL 编译器。

本文中的 QML、Qt 网络、Qt JSON 和 EditorManager 仅指现有应用外围交互适配，不属于编译执行核心。Agent 工具调用前转换为标准 C++ 数据模型，核心错误转换成界面消息发生在调用方。编译服务禁止使用 QProcess 等 Qt API，采用无 Qt 的进程封装。核心应能被不包含 Agent、不包含 Qt 的测试宿主独立调用。

该约束优先于此前宽泛的“复用 Qt”建议。若未来要求 Agent 自身也完全无 Qt，可继续替换外围网络与 UI 适配；本设计不因现有界面使用 Qt 而让编译执行核心依赖 Qt。


## 13. 可读领域代码与动态场景控制

用户手写和 LLM 生成受限 C 是同等入口。Agent 生成的代码必须使用主方案第 18 节公开的领域类型与函数，不出现地址、指针、数组下标、绑定槽位、分配器、ABI 数据布局或动作输出缓冲。不得要求用户自行管理异步创建请求编号。

SDK 是标准 C 的不透明值类型和领域函数，不生成未经支持的 C++ 实例方法语法。Agent 可以调用能力目录，取得 Entity、Vector3、具名状态、集合迭代、查询修改、模板创建与永久销毁的实际支持范围；不能猜测未实现接口。

技能与示例优先展示接近题意的代码：获取具名物体、读取位置速度、条件判断、施力、创建并配置新实体、销毁旧实体。动态增删是正式目标，不仅生成启停来冒充永久删除或真实创建；若当前版本能力不足，明确说明缺口而非伪造成功。

创建返回的待提交句柄可在同批次用于设置初值；宿主负责延迟提交及映射。Agent 解释同轮快照、创建初值、提交时机、错误、重复触发与资源上限，不把新实体描述为已参与过本轮物理。

能力声明、SDK 文档和模型上下文从同一版本化注册表生成。验收加入纯手写程序与模型生成程序行为一致、代码中无低层地址／下标操作、动态增删场景能够保存并回放；编译与执行仍遵循无 Qt／非 GPL 核心约束。
